# Учет посещаемости студентов

Учебная практика, вариант 25, аналитический этап. Python 3.12, Django 5.2, Django REST Framework, PostgreSQL 17, Docker Compose.

## Запуск

```bash
cp .env.example .env
# Укажите в .env случайные DJANGO_SECRET_KEY и POSTGRES_PASSWORD.
docker compose up -d --build
docker compose exec -e DEMO_PASSWORD='DemoAttendance!2026' web python manage.py seed_demo
```

Открыть http://localhost:8000. Демонстрационные пользователи: `admin`, `teacher`, `student`, `student2`, пароль из `DEMO_PASSWORD`. Команда не меняет пароль существующих пользователей. Данные вымышленные. Демонстрационный пароль предназначен только для локальной проверки. `.env` исключен из Git. Сервер слушает только 127.0.0.1; PostgreSQL не публикует порт на хост.

На компьютере автора `.env` и демонстрационные данные уже созданы; повторное копирование `.env.example` не требуется.

## Возможности

- Регистрация только студента; сессионный вход/выход, хеширование паролей и CSRF.
- Администратор ведет пользователей, группы, студентов, дисциплины и назначения через API.
- Преподаватель ведет занятия и отметки только по собственным назначениям.
- Студент видит только собственные отметки, занятия своей группы и свою статистику.
- Четыре экрана занятия: список, просмотр журнала, создание, редактирование. Удаление — с подтверждением.
- Статусы: присутствие, пропуск, уважительный пропуск. Неотмеченное занятие не входит в знаменатель. Диаграмма и процент рассчитываются по доступным пользователю отметкам.
- API и встроенная форма отправки запросов: http://localhost:8000/api/docs/ .

## Проверка

```bash
docker compose ps
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test --verbosity 2
```

26 автоматических тестов: роли, чужие данные, CRUD, дубли, неверные статусы, CSRF, защищенное удаление, подтверждение каскада, расчет и пустая статистика. GitHub Actions запускает тесты на PostgreSQL для push/PR.

## Работа с данными

Регистрация создает учетную запись студента. Администратор создает профиль через `/api/students/` и назначает группу. Учитель и администратор создаются администратором через `/api/users/` (включая пароль и роль).

`POST /api/attendance/` создает отметку, повторная пара занятие–студент возвращает 400; для изменения используйте PATCH по id. В форме журнала повторное сохранение обновляет существующую отметку. Связанные справочники защищены от удаления (409). Удаление занятия с отметками требует `?confirm=true` и выполняется транзакционно.

## Локальный запуск без Docker

Для быстрой разработки доступна SQLite, когда POSTGRES_HOST не задан:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
DEMO_PASSWORD='DemoAttendance!2026' python manage.py seed_demo
python manage.py runserver
```

Основная проверенная конфигурация — Docker + PostgreSQL. Для реального внешнего развертывания нужны HTTPS, защищенные cookie, собственные секреты и отдельная раздача статических файлов; текущая конфигурация учебная и локальная.
